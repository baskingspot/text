# AGENTS.md

Working notes for AI coding agents in baskingspot/text.

## What this is

Text primitives in Zig. The first module is `text.unicode`: general
categories, UAX #31 identifiers, white space, and the simple case mappings,
all generated from the Unicode Character Database. It is incubating: unstable,
with no promises about its API.

The repo owns Unicode data and the algorithms built on it. It does not own
codecs (`baskingspot/utf` does those), HTTP or HTML parsing, or CLDR locale
data until a consumer exists.

## Environment

Zig 0.17 only. The flake is the tool contract, from `baskingspot/nix`:
`nix develop` provides Zig, `ziglint`, and the base tools, and nothing comes
from the system PATH. The justfile is the command interface: `just test`,
`just lint`, `just ci`, and `just regen`. Run `just fmt` before you commit.

Tests run under testingx, the org's test runner, a lazy dependency. Every
`addTest` carries `.test_runner = .{ .path = dep.path("src/runner.zig"), .mode = .simple }`.

## The generated table

`src/tables.zig` is generated by `tools/gen.zig` from three UCD files:
`UnicodeData.txt`, `DerivedCoreProperties.txt`, and `PropList.txt`. The
release, 18.0.0, is pinned by the three URLs and their SHA-256 in the
`regen` recipe.

- Do not edit `src/tables.zig` by hand. Run `just regen` after changing the
  release, and commit the result.
- The table is committed on purpose: a consumer's build must not download the
  UCD or compile the generator. The data files are not a build dependency;
  `just regen` fetches them only when a maintainer runs it.
- The generator emits formatted Zig and is deterministic. Two runs on one
  release must produce identical bytes.
- A UCD update is a user-visible change: name the new release in the
  CHANGELOG under `## [Unreleased]`.

## Rules

- Commit messages are one line, `area: summary`, and every commit is signed. Do not rewrite pushed history.
- Gate commands on their exit codes, and claim only what you ran.
- Format with `zig fmt` and lint with `ziglint`. `just fmt` and `just lint` run both. `src/tables.zig` is exempt from ziglint because it is generated; `zig fmt` still checks it.
- This repo's GitHub settings come from `baskingspot/.github`, with `just settings`. Do not change them by hand.
- To graduate the project, follow the `baskingspot-new-repo` skill: logos, a real README, a docs site, and the audit passing.

## Changelog

`CHANGELOG.md` is one file, Keep a Changelog format, newest first. Add a bullet
under `## [Unreleased]` in the same change that alters something a user can
notice: the public API, expected behavior, the Unicode release, or the build
requirements. Docs, CI, and internal refactors do not need one unless they
change how someone uses the package.

Write from the user's side: what changed, and what they must do about it. Name
the symbol, flag, or error. One line, under Added, Changed, Fixed, or Removed.

To release, dispatch the repo's `release.yml` with the version. The workflow
moves the Unreleased section into a dated heading, sets `.version` in
`build.zig.zon`, commits, tags, and opens the GitHub release. Do not tag by hand.
