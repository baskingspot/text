# text

Unicode character data in Zig, generated from the Unicode Character Database.

`std.unicode` has the codecs and no character tables. This package answers what
a code point is: its general category, whether it can start or continue an
identifier, whether it is white space, and its simple case mapping. Every
answer comes from the Unicode Character Database at the release named by
`unicode.version`, generated by `tools/gen.zig` and checked in.

```zig
const unicode = @import("text").unicode;

if (!unicode.isXidStart(cp)) return error.NotAnIdentifier;
const upper = unicode.toUpper(cp);
```

This project is incubating. Its API will change, and it is not ready to depend
on.

## What is in it

- `unicode.category` returns the general category as a `Category`, from `Lu` to `Cn`. The group predicates `isLetter`, `isMark`, `isNumber`, `isPunctuation`, `isSymbol`, `isSeparator`, and `isOther` are that answer checked against a set.
- `unicode.isIdStart` and `unicode.isIdContinue` are UAX #31 identifiers. The `xid` forms are the NFKC-closed versions. `_` and `$` are not ID_Start; a language that allows them adds that rule.
- `unicode.isWhiteSpace` is the White_Space property, and `unicode.toUpper`, `toLower`, and `toTitle` are the simple one-to-one mappings.

Not implemented:

- Full case mapping: `toUpper('ß')` is `ß`, not `SS`. That needs `SpecialCasing.txt`.
- Case folding: there is no `caseFold`; that needs `CaseFolding.txt`.
- Scripts, blocks, normalization, segmentation, and bidi. Each one needs data this package does not carry yet.

## Install

```sh
zig fetch --save git+https://github.com/baskingspot/text
```

Add the module in `build.zig`:

```zig
const text = b.dependency("text", .{ .target = target, .optimize = optimize });
exe.root_module.addImport("text", text.module("text"));
```

`text` builds with Zig 0.17 only.

## Work on it

```sh
just ci
```

`nix develop` provides the toolchain. `just` lists the recipes, and `just ci` runs what CI runs: the tests and lint. `just regen` rebuilds `src/tables.zig` from the UCD release pinned in `build.zig.zon`; the first run downloads the archive and the result is committed.

The generator is `tools/gen.zig`. It reads `UnicodeData.txt`, `DerivedCoreProperties.txt`, and `PropList.txt`, and writes the ranges, the categories, and the mappings in one file. `just test` runs the generator's own tests with the module's.
